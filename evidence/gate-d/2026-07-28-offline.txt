## 1. Network Isolation Method
--------------------------------------------------------------------------------
Method: Option B — iptables rules (host + container isolation)

Rules applied:
  1. iptables -I FORWARD 1 -i br-578c06d518dc -o eth0 -j DROP
     (blocks all container traffic from docker bridge to external eth0)
  2. iptables -I OUTPUT 1 -o eth0 -m conntrack --ctstate NEW,INVALID -j DROP
     (blocks NEW host outbound connections to eth0; preserves established SSH
      via conntrack ESTABLISHED state matching)

Bridge interface: br-578c06d518dc (ieee_default network, 172.18.0.0/16)
External interface: eth0 (109.202.246.11/24, default route)

Rationale: Option B was chosen because the Docker stack was already running
with all 11 services healthy. iptables rules allow surgical isolation of
external traffic while preserving:
  - Loopback (lo) traffic — host ↔ Docker port mappings (localhost:8000, etc.)
  - Docker bridge (br-578c06d518dc) traffic — container ↔ container
  - Established SSH sessions — conntrack --ctstate NEW,INVALID only blocks
    new outbound connections, not established ones

Internet blocked verification:
  - Container test: docker compose exec backend curl --connect-timeout 5 http://1.1.1.1
    Result: EMPTY (connection failed/blocked) — PASS
  - Host test: curl --connect-timeout 5 http://1.1.1.1

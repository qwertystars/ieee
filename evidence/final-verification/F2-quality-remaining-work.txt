GATE 2: make typecheck (mypy, backend)
================================================================
Command:  cd /root/srijan/ieee && make typecheck
Result:   PASS — Success: no issues found in 171 source files

Initial run found 28 errors in 17 files. Two root causes:

ROOT CAUSE A — Makefile config discovery (26 import errors):
  `make typecheck` ran `mypy "$(BACKEND_DIR)/app/"` from the repo root
  WITHOUT `--config-file`. Mypy searches for config from CWD upward, not
  from the target path. Since `mypy.ini` lives in `backend/` and CWD is
  the repo root, mypy did not find `backend/mypy.ini`. The config has
  `ignore_missing_imports = True` (global backstop) plus per-module
  overrides for aiokafka, rasterio, onnxruntime, pgmpy, sklearn, mapie,
  scipy, shapely, jose, cdsetool, whisper, opentelemetry, geoalchemy2.
  Without the config, all 26 third-party import-stub errors resurfaced.

  Fix: Added `--config-file "$(BACKEND_DIR)/mypy.ini"` to both mypy
  invocations in the Makefile typecheck target (system mypy + venv mypy
  fallback). This is NOT adding new ignores — the ignores already exist
  in mypy.ini. The fix makes the command find the existing config.

ROOT CAUSE B — Real type errors in consumer.py (2 arg-type errors):
  backend/app/streaming/consumer.py:163
    error: Argument 3 to "check_and_record" has incompatible type
    "Any | None"; expected "str"  [arg-type]
  backend/app/streaming/consumer.py:170
    error: Argument 1 to "append" of "list" has incompatible type
    "Any | None"; expected "str"  [arg-type]

  `payload.get("observation_id")` returns `Any | None`, but
  `check_and_record(db, source, external_id: str)` expects `str` and
  `observation_ids: list[str]` expects `str` on append.

  Fix: Added a None guard after the `.get()` call:
    if observation_id is None:
        logger.warning("Payload missing observation_id, skipping")
        continue
  This narrows the type from `Any | None` to `Any` (compatible with
  `str`), and correctly skips malformed payloads without an
  observation_id. The guard is placed before `check_and_record` and
  `observation_ids.append`, resolving both errors.

  Test impact: `pytest tests/test_consumer_batch.py -q` → 7/7 passed.
  The None guard does not affect existing test payloads (all include
  observation_id).

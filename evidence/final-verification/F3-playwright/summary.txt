5. KNOWN FAILURE — ROOT CAUSE ANALYSIS
----------------------------------------------------------------

Test: e2e.spec.ts:122 — polling fallback — UI shows stale indicator when data is aging

Error: strict mode violation: getByRole('heading', { name: 'Situation Report' })
       .or(getByRole('heading', { name: 'Alerts' })) resolved to 2 elements

Root cause: Playwright `.or()` combinator in strict mode fails when both
alternative locators match simultaneously. The dashboard renders both
"Situation Report" and "Alerts" headings at the same time. The test's intent
is to verify that at least one panel is visible (which is true — both are
visible), but `.or()` in Playwright 1.61.1 treats the union of both locators
as a 2-element match, triggering a strict mode violation.

This is a Playwright framework API limitation, not a product defect:
  - The UI correctly renders both panels (Situation Report + Alerts).
  - The test's assertion intent (at least one panel visible) is satisfied.
  - The failure is in the test's use of `.or()` without `.first()` or
    `{ strict: false }` to disambiguate when both alternatives match.

Fix (not applied — constraint: do not modify existing Playwright test files):
  Replace `.or(...)` with `.first()` or add `{ strict: false }` to the
  toBeVisible call.

Evidence: known-failure-polling-fallback.png, known-failure-polling-fallback-error-context.md, trace-known-failure-polling-fallback.zip

# Decisions — resqnet-sota-roadmap

Architectural choices and rationales discovered during work on this plan.

_Auto-scaffolded by /start-work. Append new entries below - never overwrite._

---
- Task 4 decision: preserve legacy two-argument idempotency callers in the empty compatibility tenant while requiring `org_id` whenever a canonical payload is supplied; this avoids breaking historical adapters while preventing new cross-tenant collisions.
- Task 4 decision: use a durable per-organization audit head to detect tail truncation; verification fails closed on missing sequence, predecessor mismatch, recomputed hash mismatch, or terminal-head mismatch and never repairs audit history.
- Task 3 decision: keep `/approve` as the non-dispatch review transition and expose `/dispatch` as the explicit dual-control command transition, avoiding implicit actuation from an ordinary alert review.
- Task 3 decision: signing keys are durable organization-scoped rows rather than request-supplied public keys; an active key row is the active-user capability because the existing User schema has no status or key fields.
- Task 5 decision: reuse `raw_events` as the transactional application outbox/ledger instead of introducing a parallel table or weakening the task-4 canonical contract; duplicate external and API idempotency keys are both tenant-scoped through the existing helper.
- Task 5 decision: replay authorization is exact-role `admin` and every replay appends an `ingestion.replay` audit event binding the original failure hash; DLQ retention is a shared 30-day constant.
- Task 6 decision: use dedicated `fusion_replay_runs`, `fusion_replay_inputs`, `fusion_replay_outputs`, and `fusion_replay_errors` tables rather than overwriting the existing mutable prediction/decision projections; each run stores explicit pinned lineage and hashes.
- Task 6 decision: conflict replay fails closed with `abstain` while preserving every competing hypothesis; changed algorithm/config versions receive distinct lineage-bound decision hashes and independent run rows.
- Task 7 decision: PostgreSQL rows are canonical for safety-sensitive coordination state. Redis is a required shared freshness/transport dependency for protected authorization, atomic rate limits, and ephemeral realtime fanout; Redis outage never falls back to process-local authorization state.
- Task 7 decision: local WebSocket registries are explicitly ephemeral connection handles. Cross-instance delivery uses Redis Pub/Sub with org/incident-scoped envelopes and per-recipient ABAC filtering; durable audit/domain rows remain the recovery source for critical state.
- Task 8 decision: retain the existing IndexedDB store name and migrate legacy pending/syncing/synced records in memory, while writing all new records with explicit queued/sending/acked terminology. Legacy last-write-wins markers are interpreted as manual review rather than honored.
- Task 8 decision: do not add a migration for device identity or sync acknowledgements. The existing edge receipt ledger stores device metadata inside the append-only payload envelope, preserving the migration scope while enforcing monotonic sequences and audit lineage.
- Task 8 decision: bypass all `/api/` service-worker caching rather than infer sensitivity from URL or headers. Cache privacy is fail-closed at the service-worker boundary.
- Task 9 decision: keep development defaults available only for development/test compatibility, but make production validation reject them by setting name. Compose uses required interpolation, immutable image contents, private internal services, and no reload/source bind mounts.
- Task 9 decision: refresh rotation has zero grace because accepting an old refresh credential after use would weaken replay detection. A replayed JTI marks its Redis family revoked, denying descendant credentials.
- Task 10 decision: use one encrypted archive envelope with fail-fast SHA-256 preflight, atomic temporary artifacts, 60-second cadence, 30 successful-backup retention, external key custody, and an offsite encrypted-copy seam. Restore order is database, queue offsets, model manifests, audit chain, objects, then signing-key escrow metadata; live signing keys are never backed up.
- Task 13 decision: keep unavailable and gated datasets in the registry as explicit metadata-only `DEFERRED_EXTERNAL` records. Null artifact/split/evidence hashes are accepted only when the record says the artifact is unavailable; an available, revoked, or not-permitted artifact cannot pass. This preserves truthful provenance without silently substituting fixtures or synthetic data.
- Task 14 decision: keep the benchmark manifest as a validation-only contract when external artifacts are absent. Deterministic records are labeled `offline_contract_fixture_only`; they verify split/leakage machinery but never become real-data evidence or silently replace licensed data.
- Task 14 decision: enforce the exact pinned commit identities, 10 km geodesic buffer, incident/time ordering, immutable split hashes, test-excluded fit partitions, and named leakage families in one fail-closed CLI boundary so every run re-verifies the final-test hash.
- Task 15 decision: keep the existing GET ensemble endpoint as an explicit abstention when no validated member set is supplied, while enforcing provenance and non-scalar real raster products in the ensemble module; one SAR model cannot be silently presented as a multi-member ensemble.
- Task 15 decision: route responses always retain `review_status=draft`; only the SAR route emits `available` predictions because it has a committed real input and locally verified v2 artifact, while damage/NLP remain explicit safety degradation states until external calibration/input evidence is registered.
- Task 16 decision: a model manifest's calibration contract is valid only with a versioned, hashed, model-output artifact; unavailable artifacts use `DEFERRED_EXTERNAL`, null observed metrics, and `abstain`. The prior SAR feature-level proxy is never treated as ONNX calibration.
- Task 16 decision: direct `ModelServing` loading and route-level calibration publication both require `ContractState.available`; this closes the bypass where a caller could execute an abstaining contract directly. Recalibration cannot use final-test labels, and shift detection triggers abstention pending recalibration.
- Task 17 decision: keep the published-baseline runner as an offline command/config validator until licensed artifacts are registered. A structural report may PASS its contract checks, but every unavailable task remains `DEFERRED_EXTERNAL`, with null published values and no SOTA/superiority claim; synthetic fixtures never substitute for gated data.
- Task 17 decision: put paired incident bootstrap, five-seed median aggregation, Holm adjustment, and the practical superiority margin in a standalone statistics module so existing synthetic backend baselines and ablation APIs remain unchanged and cannot be mistaken for published evidence.
- Task 18 decision: keep robustness outcomes in pure typed helpers and a machine-readable validation policy rather than invoking unavailable ML artifacts. Every affected stale, delayed, duplicated, contradictory, adversarial, low-quality, or shifted route must abstain, be unavailable, or carry explicit uncertainty while retaining draft status and conflict provenance.
- Task 18 decision: abstention is not counted as an explicit severe false negative in selective metrics, but it is counted in coverage and must be accompanied by a safe fallback state. This preserves the distinction between a fail-closed non-decision and a silently wrong negative.
- Task 18 decision: subgroup labels are synthetic validation labels only, require at least 200 samples per eligible group, and are exported only as aggregate gaps. No raw PII or external equity claim is emitted.

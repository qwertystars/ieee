## Commit strategy

One conventional commit per todo, in wave order. Keep migrations, code, tests, evidence tooling, and documentation for one acceptance boundary together. Never commit model weights or gated data; commit manifests, hashes, licensed fixture metadata, and reproducible download/evaluation scripts. Do not merge a wave while its negative-path evidence is absent. Physical/agency work receives separate external change records and cannot be represented by software commits.

## Success criteria

The system is ready for a bounded SOTA/production claim only when: all software safety and durability gates pass; every exposed model has a canonical contract, real-input path, model-specific calibration/abstention status, and reproducible real-data results; published baselines and confidence intervals support any superiority claim; CAP/OGC/SensorThings contracts pass selected profiles; production-parity recovery, security, offline, audit, and human-factor gates pass; and the staged shadow/field exercise meets preregistered thresholds. Otherwise the release report must state the exact PASS/FAIL/DEFERRED boundary.

## Methodology

Each capability was verified by reading the actual source files (paths cited
below), grepping for stub/placeholder patterns, and cross-referencing the ORM
models against Alembic migration 0001. Docker and a live PostgreSQL instance
were NOT available in this environment (see `evidence/baseline/2026-07-26/environment.txt`),
so runtime verification is deferred to Gate A. Classifications are grounded in
source code, not test execution.

## Classification legend

| Classification | Meaning |
|----------------|---------|
| verified working | Source present, tests pass, runtime confirmed |
| implemented but unverified | Real source present; tests exist but not run in this env (no Docker/Postgres) |
| partial | Real source present but incomplete (missing endpoints, missing wiring) |
| stub | Route/endpoint returns `{"status":"ok"}` or placeholder |
| broken | Source present but known-defective (wrong type, drift, crash) |
| missing | No source exists |
| historical | Source removed (e.g. Cloudflare `platform/` deleted) |

## Key findings

1. **Engine layer is remarkably complete** — ~60 real engine files across fusion,
   perception, optimizer, twin, knowledge, sensing, eval, streaming, realtime,
   auth, ABAC. The gap is integration wiring, not engine development.

2. **API surface is mostly stubs** — 5 of 9 registered routes return
   `{"status":"ok"}`. Two real routers (health.py, realtime/manager.py) are NOT
   registered in main.py.

3. **Migration drift is severe** — 13 entity tables missing columns; 8+ tables
   created at runtime via `ensure_table()`/`create_all()`; native PG ENUM vs
   VARCHAR mismatch; `sources` table completely orphaned.

4. **Frontend is near-empty** — App.tsx is 5 lines; deps installed but unused;
   no routing, auth, API client, PWA, or offline support.

5. **ORG_ID mismatch** — `seed/ids.py` uses `"demo_org"` but `auth/seed.py`
   uses `"org_demo"`. Demo users and demo data are in different orgs.

6. **Security weaknesses** — health endpoint leaks DATABASE_URL; wildcard CORS
   with credentials; no JWT secret validation; test endpoint unrestricted.

7. **No worker container** — ConsumerManager exists but is never started; no
   dedicated worker service in docker-compose.

8. **Docker unavailable in audit environment** — all "implemented but
   unverified" items require Gate A (Docker + PostgreSQL) for runtime
   confirmation. See `evidence/baseline/2026-07-26/environment.txt`.
